## 1. 用户诉求与期望形态（原始表述）

用户描述的期望形态（原文要点）：

- 模拟盘 = **真实行情、真实规则、只差真钱**；
- AI 一开始**完全按策略交易**；
- 随着用户与 agent 讨论，策略**逐步完善**；
- agent 可以**自动化交易，但需要人工审批**；
- **每次交易都要有相应的惩罚**（像手续费一样）；
- 每笔交易**都留痕**，用户可点时间戳知道"为什么这时候这样交易"；
- 单笔交易可以**拿出来和 agent 单独交流**，用来优化后面的决策；
- 希望**双 agent**：主 agent 聊天答疑，另一个 agent 长期在模拟盘交易，"越交易策略越完善"；
- 两者**记忆分开存放**，需要时再合并取用；
- **不要额外造新模块，能复用就复用**；
- 希望模拟盘 agent **接入更多外部信息接口**以获得"更高的智能"。

## 3. 约束与不可协商的原则（本项目已有的克制决定）

1. **执行层必须确定性**：同一份输入重跑必须得到同一结果（可复现、可与回测对照、可幂等重放）。
2. **不预测股价**：禁止点位预测与"必涨/必跌"类表述（`react_agent.py:44-45`、`tool_registry.py:686`、`app.py:679` 三处硬约束 + `tool_audit` 的合规黑名单）。预测类模型（LGB/Transformer/DQN）只作低权重诊断，**不参与买卖决策**。
3. **单一执行管线**：所有工具调用必须过 `tool_pipeline`（边界控制文档 P4b 的教训：绕过管线的入口会静默跳过所有策略）。
4. **单一真相源**：数据只在 Java（MySQL）；Python 通过内部 API 读写，且内部 API **形状上没有 update/delete**。
5. **证据制**：模型产出的结论必须能引用可验证的证据（记忆事实的取代链、审计的数字溯源、审查的 JSON 路径）。
6. **fail-open**：所有旁路（记忆、计量、审计、裁决、审查、推送）失败都不得影响主流程，且必须在 `/health` 可见。

## 4. 目标设计

### A. 双角色，同一运行时（**不新建第二个 agent 运行时**）

| | 主 agent | 模拟盘 agent |
|---|---|---|
`role` | `chat` / `strategy` | `paper_trader` |
工具集 | `core|market|strategy|model|fundamental` | 新增 `paper` 模式（现有只读工具 + 账户读取 + 写动作需审批） |
记忆切片 | `user/*`（主观偏好、约束、目标） | `strategy/<id>/*`（客观表现 + 交易经验） |
触发 | 用户消息 | 15:30 定时 / 5 分钟价格事件（**常驻的是任务，不是进程**） |
职责 | 答疑 / 生成与修改策略 / 解释某笔交易 / 汇总建议 | 守规则结算 / 复盘 / 发现异常 / 提议（**绝不自己放宽规则**） |

**纪律**：模拟盘 agent 永远不能修改自己的约束（止损、仓位上限、入场/出场规则）——只能提议。

### B. 记忆作用域分离 + 按需合并

- **不新建存储**：靠现有 `subject`（`user` / `strategy:<id>` / 代码）与账本 `meta.role` 区分作用域。
- **为什么必须分**：取代链以 `(subject, predicate)` 为键。用户亲口说的 `user.stop_loss_pct=8` 与
  模拟盘经验 `strategy:42.observed_stop_loss_too_tight` **必须是不同 subject**，否则后者会取代前者。
- **合并的规则**：**只在读取时（渲染层）合并，永不写回**；注入时分区块渲染（"关于你" / "关于这个策略"）。
  跨作用域的综合结论（如"按你的风险偏好，这个策略波动太大"）**只由主 agent 说出**，并按需单次、可审计。
- **交易经验的来源必须是痕迹，不是对话**：复用 `consolidate` 的结构化抽取管线，写进现有 `lessons` 表
  （`task_type=paper_trading`），且**必须引用痕迹字段**。

### C. 交易痕迹（trace）——"点时间戳看为什么"的唯一实现方式

新增 `paper_trade_trace`（一行 = 一次结算决策）：

```
identity   strategy_id / strategy_revision_id / settlement_kind(daily|realtime) / trigger(cron|price_refresh|start)
input      bar_date, bar_time, bar_ohlc(open/high/low/close/volume)   ← 可复算的关键
           indicators(命中的指标值), params(策略参数快照)
account    结算前/后：cash / shares / avg_cost / high_watermark / equity
decision   buy|sell|skip + matched_conditions(结构化) + skip_reason
           skip_reason ∈ {market_closed, no_bar, limit_blocked, t1_blocked,
                          insufficient_cash_for_one_lot, rule_not_met, data_unavailable}
provenance rule_version + engine_version
integrity  trace_hash（对上述输入做哈希）
```

三条设计要点：
1. **"没成交"也要留痕**（`decision=skip`），因为用户最常问的是"为什么没动"（G4）。
2. **`engine_version`**：引擎变更后历史交易仍可解释（否则"为什么上周那笔和现在重算不一样"无解）。
3. 前端呈现三段式：`规则命中 → 计算过程 → 成交/跳过结果`，并提供「用同样输入复算」。

### D. 观察 → 报告 → 讨论 → 引擎裁决 → 版本

**这是本方案的核心机制，也是"越交易越完善"的落地方式。**

```
观察（确定性）   五类判据，全部由代码/引擎生成，不需要模型"有灵感"
      ↓
报告（分级）     每日（静默入消息中心）/ 每周（沉默期报告）/ 越界立即推送（阈值触发）
      ↓
讨论          用户与 agent 讨论 → 每个主张必须**命题化**为可回测断言
      ↓
引擎裁决      多时段（≥3 段）× 多标的（≥5 只）批量回测判定，**不由模型判定**
      ↓
预期登记      成立则落 expectation（可验证预期，非股价预测）
      ↓
采纳/拒绝     用户点；**模型必须能说"不"**（结构化输出 + 反证据）
      ↓
新版本        写 strategy_revision（原因 + 预期 + 改前参数）
      ↓
N 周后回填    「这次改动到底有没有用」自动回填
```

#### D1. 建议来源白名单（五类，禁止模型自由发挥）

| 类别 | 确定性判据 | 需要模型做什么 |
|---|---|---|
① 沉默期异常 | 连续未触发天数 vs **历史沉默期分位数** | 讲人话 |
② 越界 | 回撤/波动超过**用户亲口说过的**容忍度（记忆里的 `max_drawdown_tolerance`） | 讲人话 |
③ 规则互斥/退化 | `strategy_review` 的确定性 9 项 | 不需要 |
④ 参数系统性问题 | 同参数在**多时段 + 多标的**上系统性更差 | 不需要 |
⑤ 执行异常 | 涨停挡单 / 无 bar 跳过 / 资金不足一手 / 审批延迟成本 | 讲人话 |

**为什么必须白名单**：模型的"想法"来自**它刚看到的那段行情**，而策略改动必须**样本外**验证才有意义。
否则会形成自我强化的过拟合循环：

> 看着刚发生的行情提建议 → 用户被说服 → 改策略 → 在同一段历史上回测"更好看" → 更有信心 → 未来更差

#### D2. 讨论协议（防止模型顺从用户）

1. 命题化：把主张变成可回测断言（"slow 60→55，回撤 ≤ -14%"）；
2. 引擎裁决：多时段 × 多标的；
3. 预期登记：`expectation`（可验证）；
4. 采纳/拒绝：模型输出 `stance ∈ {agree, disagree, insufficient_evidence}` +
   `counter_evidence`（必须引用回测结果）+ `what_would_change_my_mind`。
   **"无证据的同意"直接丢弃**（复用 `review.py` 的"必须引证据"纪律）。

#### D3. 空转期报告（三层，前两层零模型成本）

| 层 | 内容 |
|---|---|
事实层 | 当前价与阈值距离、连续未触发天数、账户净值、最近结算结果（含 skip 原因） |
统计层 ★ | "历史平均每 23 天触发一次；当前沉默 12 天，处于历史沉默期 60% 分位" |
解释层 | 一句话人话 + 是否需要行动 + 可讨论选项（每项带回测数字，由模型引用前两层组织语言） |

★ 统计层是解决"空转期零信息量"的关键单项：它把"干等"变成"有依据的等待"，
回答"我是在等，还是它坏了"。实现成本≈一次历史聚合。

#### D4. 打扰门禁（必须由阈值触发，不能由模型判断）

| 时机 | 内容 | 门槛 |
|---|---|---|
每日（静默） | 有结算就写一条到消息中心 | 固定：有/无 |
每周 | 沉默期报告 + 净值变化 | 固定节奏 |
立即推送 | 越界 / 执行异常 / 规则退化 / 连续 N 天沉默 | **确定性阈值** |

### E. 审批（打通 G5）

```
agent 提议动作 → pending_action{动作类型, 参数, 依据(引用痕迹字段), 到期时间}
   → 推送（复用消息中心）→ 用户批准/拒绝（可附理由，进账本）
   → 批准时下发**一次性令牌**（即一直未使用的 approvals 字段）
   → 落成一条**指令**{idempotency_key, 生效条件, 到期} → 执行 → 写痕迹 → 通知
```

动作分级：
- **免批**：只读、报告、建议；
- **需批**：暂停模拟盘、下调仓位上限、单笔自主交易、参数变更；
- **禁止**：放宽止损、改成与用户原话相反的规则、任何真实下单。

补充机制（针对已知弱点，见第 6 节 R2）：
- **影子模式**：批准前先"如果批准，它会做什么"（不执行、只展示）；
- **额度内免批**：单笔 ≤ 阈值且当月次数未超时免批，其余必批；
- **延迟成本如实记录**：因审批延迟导致的成交价差必须写进痕迹并在收益里单列。

### F. 惩罚与配额（**与 P&L 分离**）

- **摩擦成本（已有）**：佣金 max(费率,5 元) / 卖出印花税 0.05% / 滑点 → 这部分属于"真实口径"。
- **自主决策成本（新增）**：对**非规则触发**的 agent 主动交易额外计一笔**确定性惩罚**（固定基点或固定金额）。
- **关键约束**：惩罚**不进 P&L**，而作为**独立的额度消耗 + 评级**（"本月自主交易 5/10 次"）。
  理由：若计入 P&L，模拟盘收益率就不再等于"实盘会怎样"，与回测对照也被污染（见 R1）。
- **分账统计**：`规则交易` 与`自主交易`的成本、收益、净贡献完全分开 → 用数字决定自主权扩大还是收回。

### G. 数据模型新增（仅两张表 + 一个加列）

| 对象 | 用途 | 关联缺口 |
|---|---|---|
`paper_equity_snapshot`（新，每日一行：date/equity/cash/shares/price） | 净值曲线、回撤、与回测对照 | G2 |

## 5. 外部信息接入（用户诉求："接入更多接口以获得更高的智能"）

### 5.1 接纳判据（先定规则，再定清单）

**唯一判据：它是否让 4.D1 的某一类观察变得"可判定"或"可解释"。**
不改变任何判据的来源，只会增加上下文成本、注入面（外部正文不可信）与维护面。

架构上"加一个源"的成本很低（这是本项目的强项）：
在 `external_source.DATASETS` 声明（provider/TTL/上游）+ 在 `tool_registry` 加一个 `ToolSpec`
（`provenance=external`、`trust=low|medium`、`source=…`、`cost_class`、`result_budget_chars`），
即自动获得：门禁与冷却、分级 TTL、不可用时从装填中摘除、`<external_data>` 包裹与来源标注、审计与计量。
**成本在数据映射与验证，不在框架。**

### 5.2 候选清单（按"服务于哪一类观察"排序）

| 优先级 | 外部信息 | 服务的观察类别 | 现状 |
|---|---|---|---|
P0 | **交易日历**（休市/半日市/临时休市） | ⑤ 执行异常、① 沉默期 | 缺失；现在是靠 `bar_date_missing` 兜底 |
P0 | **涨跌停/停牌（ST、科创、北交所不同幅度）** | ⑤ 执行异常 | 现在是"按开盘价推算"，近似 |
P1 | **指数与板块行情**（判断"是个股跌还是大盘跌"） | ① 沉默期、解释"为什么今天跌" | 部分有（批量行情），指数/板块缺失 |
P1 | **新闻/公告/研报**（分类型搜索 + 事件 JSON） | 解释层（"跌的原因"） | **设计完备、零代码**（`2026-09-05-news-module-design.md`）；注意 `trust=low`，**只能当线索** |
P2 | 资金流/北向/龙虎榜 | 解释层 | 无 |
P2 | 同业/同板块标的（用于横向对照） | ④ 参数系统性、解释层 | 无 |
P2 | 财报与业绩预告（事件化） | ①② 解释层 | 有 `get_financial_abstract`，未事件化 |
P3 | 宏观日历（利率、数据发布） | 解释层 | 无 |
P3 | 用户侧：自选股、预警、持仓成本 | ② 越界 | 自选/预警有；**持仓成本刻意不写**（同花顺同步只增不改） |

### 5.3 三条反例（"更多信息 ≠ 更高智能"）

1. **不改变判据的源就是纯成本**：上下文预算有限（新闻类工具的实测预算是 3600 字符，
   而指标类很小）；塞满正文会挤掉指标与对话历史。
2. **外部正文的 `trust=low` 是硬属性**：它只能当线索。用外部正文下结论，等于给第三方内容开了一条
   写入长期记忆的路径（本项目已在账本层禁止存外部正文，只存"取到几条"+ 落盘编号）。
3. **接入 ≠ 会用**：模型不会因为拿到更多源就变聪明；选择能力取决于工具描述与 golden set 的覆盖
   （见 `tests/tool_eval`）。**每加一个源都应同时加一条 golden set 用例**，否则无法知道它有没有被正确使用。

## 6. 已知风险与自我批评（**请评审者重点挑战这些**）

**R1 惩罚污染收益口径**：模拟盘加了实盘不存在的成本，其收益率就不再等于"实盘会怎样"，
与回测的对照也失效。→ 本文的处理：惩罚不进 P&L，改为额度消耗 + 独立评级（4.F）。

**R2 日线策略 + 人工审批 = 永远慢半拍（本方案的根本矛盾）**：日线信号出现 → 提请审批 →
用户数小时后看到 → 次日开盘价已变。审批的时效与人的响应速度不匹配。
→ 三种可能出路：(a) 接受延迟执行并如实记录延迟成本；(b) 改为"额度内免批 + 事后审计"；
(c) 只对低频、非时效敏感的动作要求审批。**本文未最终决定，列为待定（4.G/第 8 节）。**

**R3 过拟合循环**：见 4.D1。若白名单与多时段多标的验证被削弱，整个"讨论优化"会变成"越讨论越差"。

**R4 模型顺从用户**：讨论中模型倾向于同意用户。→ 处理：命题化 + 引擎裁决 + "无证据的同意即丢弃"。

**R5 空转期零信息量**：日线策略可能数周不交易，而产品的全部价值叙事都围绕"交易"。
→ 处理：4.D3 的三层报告 + 沉默期分位；但**"用户会不会看报告"这个假设尚未验证**。

**R6 过度设计（我自己的批评）**：本方案有 8 个可动部件（痕迹、审批、惩罚、配额、分账、角色、
记忆作用域、反事实回放），而用户目标是"验证一个策略想法"。**很可能应该先只做
"每日净值 + 痕迹 + 一句人话 + 空转期报告"，验证用户是否会看，再决定其余部件是否要建。**

**R7 审批疲劳**：批准若干次后用户会无脑同意，安全感是假的。→ 处理：影子模式 + 预期数字 +
额度内免批 + 只对重要动作要求审批。

**R8 "越交易越完善"可能永远不成立**：日线策略一个月可能只触发 1–2 次，**样本量不足以判断规则好坏**。
→ 处理：报告必须给统计显著性反馈（"当前 2 次交易，不足以判断，至少需要 ~20 次"），
否则用户会在第 3 周因为"什么都没发生"而放弃。

**R9 改动本身缺少纪律**：每次都能找出"可优化点"→ 不断改 → 每个版本都跑不满样本 → 永远得不出结论。
→ 处理：改动冷却期 + 每月上限 + N 周后回填"这次改动有没有用"（4.D 末端）。

**R10 与正式盘的差距未向用户显式声明**：现在能对到"日线级 + 次日开盘成交 + 涨跌停挡单 + T+1 + 费用"，
**对不到**盘口深度、委托排队、部分成交、分钟级撮合。若不在界面上写明，用户会以为等同实盘，
"惩罚"也会被误读为市场冲击成本。

**R11 成本累积**：每日每策略复盘 + 每笔解释 + 讨论 → token 成本随策略数线性增长。
现有 `metering` 有计量，但**没有按角色/用途的账单**。

## 7. 失败与降级（fail-open 矩阵，全部需在 `/health` 可见）

| 旁路 | 失败表现 | 保护 |
|---|---|---|
记忆读写 | 无记忆 / 少一条记录 | 异常只记日志；坏摘要宁可不落库；`context_block` 恒为字符串 |
结算 | 跳过当日 | `bar_date_missing` 判定；幂等键保证可重跑 |
轨迹写入 | 少一条痕迹 | 不影响成交；缺口在报告里显式标注 |
复盘 / 报告 | 当日无报告 | 下次再试；报告生成失败不得影响结算 |
审批通道 | 动作无法执行 | 拒绝并告知（**fail-closed**：没有审批就不执行） |
外部源 | 该源不可用 | 门禁标记不可用 → 从装填中摘除 → 冷却 → 半开重试；报告降级为"该数据暂不可用" |
推送 | 用户收不到 | 落消息中心（可回看）；前端断线重拉已修复 |

## 8. 分阶段路线与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
**P0（砍半版，先做）** | `paper_equity_snapshot` + `paper_trade_trace`(含 skip) + **一句人话解释** + **空转期周报（含沉默期分位）** | 能画净值曲线；随机抽 5 笔交易/跳过，用户不看代码能明白"为什么这一刻"；空转两周后用户仍知道系统在正常工作 |
**P1** | 盘后复盘写入消息中心；时间轴 + 抽屉（异常优先） | 用户会主动点开（**这是 R6 的关键验证点**） |
**P2** | `strategy_revision` + 讨论协议（命题化 + 引擎裁决 + 反证据） + 建议白名单 ①–⑤ | 建议采纳率与 expectation 命中率可统计；无一条建议未经多时段多标的验证 |
**P3** | 审批通道（`pending_action` + 一次性令牌 + 审批卡 + 影子模式） + 首批低风险动作 | 每个自主动作都有审批记录与幂等键；重放安全；延迟成本被如实记录 |
**P4** | 自主交易 + 配额/惩罚（不进 P&L） + 分账统计 | 能回答"自主交易扣掉成本后是否为正贡献" |
**P5** | 单笔/区间与 agent 交流 + 反事实回放 | 回答中每条引用都能对上痕迹字段（沿用 `review` 的证据制） |

**贯穿要求**：每个阶段新增的能力都要能挂进现有评测门禁（`tool_eval` / `memory_eval` / `review_eval`
的形状：golden set + 阈值 + 可 CI 的离线部分）。

## 9. 明确不做（scope 边界）

- ❌ 不把逐笔买卖决策交给模型（破坏可复现/可回测对照/幂等）；
- ❌ 不预测股价、不输出点位预测（沿用既有硬约束）；
- ❌ 不做"总调度 agent 调子 agent"（沿用既有决策）；
- ❌ 不新建第二个 agent 运行时 / 第二个数据源 / 文件式记忆；
- ❌ 不做分钟级撮合引擎、盘口与排队模拟（R10）；
- ❌ 不允许 agent 放宽自身约束；
- ❌ 不把外部正文写进长期记忆。

## 10. 待定决策（需要用户拍板）

**D1 惩罚形式**：固定基点（如每笔 0.1%）／固定金额／**配额制**（每月 N 次，超了加倍）。
本文倾向：**配额 + 固定基点**，且**都不进 P&L**。

**D2 审批粒度**：每笔必批／**额度内免批、超额必批**／批量批。本文倾向中间项。

**D3 解释文本是否落库**：结构化痕迹为准（可复算）／同时存模型生成的解释文本（好读但会过期/漂移）。
本文倾向：**痕迹为唯一真相源，解释文本按需生成，落库时标注"由某模型在某时生成"**。

**D4 痕迹粒度**：每笔成交 + 每次跳过（本文倾向）／每个结算日一行。

**D5 空转报告的节奏与门槛**：周报是否固定发送（本文倾向固定，避免"模型判断值不值得说"）。
